# OpenNest 设计文档

> 版本 0.1 ｜ 2026-10-25 ｜ 状态：已评审
> 产品：OpenNest —— 免账户、直连存储的文件客户端（桌面 + Android）

---

## 1. 产品概述

### 1.1 产品定义

OpenNest 是一个**无需注册、无需登录**的文件客户端。首次启动时，它在本机回环地址上拉起一个内嵌的 OpenList 引擎（受管子进程），然后只问用户一个问题：*你想连接哪个存储？*

用户添加**存储源**——本地目录、WebDAV、对象存储、SFTP、FTP、SMB、网盘、分享链接，或另一台 OpenList 服务器——随后在统一界面中浏览、预览、传输和管理所有源中的文件。引擎管理员口令随机生成并存入系统钥匙串，用户全程看不到任何账号概念。

### 1.2 设计原则

| 编号 | 原则 | 含义 |
|---|---|---|
| 一 | 免账户 | 无注册、无登录页、无用户概念；服务端凭据由客户端自动管理 |
| 二 | 直连存储 | 首启到第一个文件列表不超过三次点击 |
| 三 | 统一文件库 | 所有源共享侧边栏、浏览器与传输队列 |
| 四 | 视觉一致 | 效果图即验收标准，数值、间距、层级不得自由发挥 |
| 五 | 可靠优先 | 本地元数据、断点续传、网络异常降级只读 |

### 1.3 核心旅程

```
安装 → 首次启动（无登录）→ 添加第一个存储 → 选择驱动
     → 填写动态表单 → 测试并保存 → 浏览 / 预览 / 传输
```

### 1.4 目标用户

已部署 OpenList/AList、网络附加存储、Nextcloud/WebDAV、对象存储或 Linux 服务器的自建用户。他们的共同点是：不愿意为又一个工具注册账号。

## 2. 整体架构

### 2.1 五层结构

```
┌──────────────────────────────────────────────────────────────┐
│ 界面层（Flutter，桌面 / 移动双分支）                            │
│   引导 · 文件浏览 · 传输 · 预览 · 设置                          │
├──────────────────────────────────────────────────────────────┤
│ 状态层（riverpod StateNotifier）                               │
│   sidecar · sources · files · transfers · settings             │
├──────────────────────────────────────────────────────────────┤
│ 服务层（纯 Dart）                                              │
│   进程管理 · 引擎接口客户端 · 驱动表单模型 · 传输引擎 · 凭据库    │
├──────────────────────────────────────────────────────────────┤
│ 数据层                                                        │
│   单一 SQLite（opennest.db）· 系统钥匙串                        │
├──────────────────────────────────────────────────────────────┤
│ 进程层                                                        │
│   OpenList 引擎（随包分发的可执行文件）                          │
│   127.0.0.1:<随机端口> · userdata 数据目录 · 本地数据库          │
└──────────────────────────────────────────────────────────────┘
```

### 2.2 为什么内嵌引擎

OpenList 的 Go 内部包（`internal/`）不对外暴露，无法作为库引用。把官方可执行文件当作受管子进程运行，是复用其 85 个驱动、存储配置模型与稳定接口的唯一途径。代价是每平台约 35 兆体积，换来的是整个驱动生态与一条统一的接入路径。

### 2.3 进程状态机

```
空闲 → 解析（数据目录/可执行文件/端口）→ 拉起 → 等待健康检查（≤30 秒）
     → 登录 → 就绪
                ↓ 失败
             换端口重试（≤10 次）→ 失败态（可见错误 + 日志尾部）
就绪 → 停止中 → 空闲
```

三条硬约束：

1. **先判重再启动**：读 `userdata/sidecar.pid` 并探测健康检查接口，已在运行则复用端口与令牌。引擎自身没有进程锁，双开会写坏数据库。
2. **端口不能交给系统随机**：配置文件里的端口写 0 时，日志只打印 `:0`，真实端口无处可查。必须先绑定空闲端口探测出可用值，写入配置后再启动。
3. **首帧不等待**：先渲染界面，把启动流程放进启动页的状态里跑，避免冷启动黑屏或白窗。

### 2.4 免账户的三段链路

```
首次启动 → 生成 32 位随机口令 → 写系统钥匙串
        → 以环境变量注入子进程 → 引擎首次初始化时创建管理员
        → 登录换取令牌 → 令牌写钥匙串
        → 之后所有请求带令牌（裸令牌，无 Bearer 前缀）
```

钥匙串条目丢失时，用引擎自带的 `admin set` 命令重置口令兜底。

## 4. 存储对接方式

### 4.1 首次启动引导

1. 解析数据目录：桌面为程序目录下的 `userdata/`，Android 为应用私有目录。
2. 解析可执行文件：桌面为同目录的 `openlist.exe`；Android 为系统原生库目录下的 `libopenlist.so`。
3. 生成配置文件：绑定 `127.0.0.1`、随机端口、随机签名密钥、SQLite、关闭对象存储/文件传输/远程登录等附加监听。
4. 注入随机管理员口令，拉起子进程。
5. 轮询健康检查接口，直到返回成功（超时 30 秒）。
6. 登录换取令牌，写入钥匙串。
7. 标记初始化完成，进入引导页。

### 4.2 存储源映射

| 概念 | 实现 |
|---|---|
| 源身份 | 引擎侧存储记录的编号，本地只存展示偏好 |
| 挂载路径 | `/s_<八位十六进制>`，全局唯一 |
| 展示名 | 引擎侧的备注字段 |
| 驱动名 | 驱动注册表键名（含空格，请求必须走查询参数编码） |
| 表单 | 一次请求取回全部驱动的字段定义，按名称分组展示 |
| 测试连接 | 创建后立即列根目录，成功保留、失败删除并内联报错 |
| 编辑 | 更新必须携带编号；驱动参数整体序列化为字符串提交 |

### 4.3 全量驱动表单

一期覆盖引擎全部 85 个驱动。表单由字段定义动态生成，控件对应关系：

| 字段类型 | 控件 |
|---|---|
| 字符串 | 单行输入 |
| 数字 | 数字输入（兼容超大整数） |
| 布尔 | 开关 |
| 多行文本 | 多行输入 |
| 枚举 | 自绘下拉（选项可能是逗号分隔串，也可能是「值/标签」对象数组） |
| 其他或空 | 按字符串处理 |

需要额外处理的真实情况：默认值可能是布尔或数字而非字符串；字段名含 `password`、`token`、`secret`、`key`、`cookie`、`private` 时按机密字段渲染并加「仅本机」徽标；驱动公共字段（代理策略、排序、缓存时长、签名开关等）必须一并提交，否则直链与排序会异常。

扫码或浏览器授权类驱动（部分网盘）无法在客户端内完成授权，表单顶部给出明确提示并附帮助文案。

### 4.4 通道选择

| 操作 | 通道 |
|---|---|
| 列目录、元数据、搜索 | 引擎文件接口（分页） |
| 上传 | 引擎流式上传接口 |
| 下载、预览、播放 | 签名直链 + 范围请求 |
| 写操作 | 引擎目录/重命名/移动/复制/删除接口 |
| 源管理 | 驱动元数据接口与存储增删改查接口 |

### 4.5 数据目录

```
userdata/
├── opennest.db     全部本地数据（SQLite，见下表）
├── config.json     引擎配置
├── data.db         引擎数据库
├── logs/           引擎日志
└── sidecar.pid     引擎进程号
```

| 表 | 内容 |
|---|---|
| `settings` | 标量偏好与 `ol_prefs` 的每个字段（key/value/kind，保留类型） |
| `ui_state` | 每个存储源的浏览位置、排序字段与方向 |
| `download_dirs` | 每个存储源的下载目录 |
| `resume_positions` | 播放续播位置（按源 + 路径） |
| `listing_cache` | 离线目录快照（最多保留 24 个） |
| `transfer_tasks` | 传输记录 |
| `favorites` | 收藏 |

所有路径从程序可执行文件位置推导，不使用系统数据库目录，保证便携。不可写时回退到用户本地应用数据目录。

## 5. 数据流转逻辑

### 5.1 首启引导

```
启动 → 单实例判定 → 渲染界面 → 启动页 → 解析路径
→ 生成配置（随机端口/口令）→ 拉起引擎 → 轮询健康检查
→ 登录 → 令牌入钥匙串 → 就绪 → 引导页或文件页
```

### 5.2 添加存储源

```
选择驱动 → 读取字段定义 → 渲染表单 → 测试
→ 创建存储记录 → 列根目录 → 成功保留 / 失败删除并提示
→ 写入展示偏好 → 侧边栏刷新 → 跳转该源根目录
```

### 5.3 浏览目录

```
进入路径 → 请求列表 → 内存缓存 → 渲染
→ 四态：骨架 / 内容 / 空 / 错误（离线降级只读）
→ 滚动到底自动加载下一页
```

### 5.4 下载

```
发起下载 → 取签名直链 → 范围请求分段写入
→ 断点续传（记录已下载字节）→ 校验长度 → 完成
```

### 5.5 上传

```
选择文件或拖入 → 入队 → 并发调度
→ 流式上传 → 进度回调 → 完成 / 失败重试
```

### 5.6 远程服务器级联

```
添加源（驱动选「OpenList」）→ 填服务器地址与令牌
→ 引擎内部级联 → 与其它源同一套浏览界面
```

### 5.7 视频预览

```
打开视频 → 签名直链 → 播放器范围请求 → 拖动进度只取对应片段
→ 播放位置按文件持久化
```

## 7. 风险与合规

| 风险 | 影响 | 对策 |
|---|---|---|
| 许可为 AGPL-3.0 | 分发必须开源 | 仓库根附许可证，关于页与说明文档标注来源 |
| 移动端执行随包二进制 | 系统限制可写目录执行 | 二进制以原生库形式打包，由系统解压到可执行目录；每次启动重新解析路径 |
| 16KB 页对齐 | 新设备可能无法启动引擎 | 已实测：官方 v4.2.8 的 Android 二进制为 **4KB 对齐**，16KB 页设备（部分 Android 15+）无法执行。构建流水线打印程序头报告；后续可自行编译引擎并加 16KB 链接参数 |
| 部分驱动需扫码授权 | 无法在客户端完成 | 表单给出明确提示；账号密码与令牌类驱动全部可用 |
| 引擎崩溃 | 功能中断 | 健康检查 + 自动重启一次 + 可见错误态与日志 |
| 孤儿进程 | 数据库损坏 | 进程号文件 + 启动前探测 + 退出时强制结束 |
| 端口冲突 | 启动失败 | 探测排除单实例端口，重试上限十次，真实端口单独持久化 |
| 首次启动耗时 | 观感差 | 先渲染界面，启动页显示进度，失败可重试 |
| 安装包体积 | 下载成本 | 使用精简版引擎；后续可拆分架构 |
| 凭据落点 | 源密码保存在本地数据库 | 说明文档与设置页明示；系统钥匙串只放引擎口令与令牌 |

## 8. 实施路线图

| 阶段 | 目标 |

## 附录：架构决策记录

**决策一：以内嵌引擎代替原生协议适配器。**
引擎内部包不可引用，自研各协议适配器需为每种协议找库并自行维护。选择随包分发官方可执行文件，换取全部驱动与统一配置模型；代价是体积与进程管理复杂度。

**决策二：数据层只用 SQLite。**
v0.3.0 起取消便携 JSON 文件，所有本地数据并入 `opennest.db`：不同形状的数据分表存放，写入走事务与 250ms 合并，读取走内存镜像保证同步取用。单一存储消除了两套持久化路径与原子写/回退分支，也让「备份/迁移」只需拷贝一个文件。

**决策三：远程 OpenList 服务器作为一种存储源。**
复用引擎内置的级联驱动（地址 + 令牌），不另写远程客户端，避免第二套网络栈。

**决策四：一期只做桌面与安卓。**
构建流水线已有两端方案，苹果与桌面 Linux 需额外签名与验证，放到后续阶段。

**决策五：界面数值以效果图为准。**
设计令牌从效果图重新抽取并关闭全局字号放大，确保一比一还原。
